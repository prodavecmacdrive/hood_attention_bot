# Контекстный анализатор (Context Analyzer)

## Описание

Этот модуль предназначен для анализа **контекста** вокруг сообщения-триггера. Вместо того чтобы реагировать на одно сообщение, он анализирует **цепочку сообщений** из недавней истории, чтобы понять полную картину события.

## Проблема

Первая нейросеть реагирует на ключевые слова или семантически похожие сообщения, но часто упускает **контекст**:
- **Что именно летит?** (ракета, шахед)
- **Откуда и куда?** (направление, цель)
- **Насколько достоверна информация?** (подтверждено несколькими источниками)

**Пример:**
Сообщение `шишковка, внимательно` является триггером, но не несет информации о типе угрозы.

## Решение: Анализ на лету на основе истории

### 1. Сбор истории (`history_loader.py`)

- При запуске команды `/admin_load_history` бот в фоновом режиме загружает историю сообщений из всех отслеживаемых каналов за последние **2 месяца**.
- Сообщения сохраняются в новую таблицу `historical_messages` в базе данных.
- При последующих запусках загружаются только новые сообщения.

### 2. Анализ контекста (`context_analyzer.py`)

Когда первая нейросеть находит релевантное сообщение (триггер), запускается `ContextAnalyzer`:

1. **Загрузка недавних сообщений**: Из БД извлекаются все сообщения из всех каналов за последние **30 минут**.
2. **Поиск кластера событий**:
   - Анализатор находит все сообщения, семантически близкие к сообщению-триггеру (сходство > 70%). Это формирует "кластер события".
   - Это позволяет объединить сообщения из **разных пабликов**, описывающие одно и то же событие.
3. **Анализ кластера**:
   - **Определение типа угрозы**: По ключевым словам (`шахед`, `ракета`, `КАБ` и т.д.) определяется наиболее вероятный тип угрозы.
   - **Извлечение локаций**: Находятся упоминания районов Харькова.
   - **Извлечение направления**: По шаблонам (`летить в бік...`, `курс на...`) определяется направление движения.
4. **Формирование summary**:
   - Генерируется краткая сводка, например:
     ```
     🎯 Тип: Шахед
     📍 Локації: Салтовка, Пятихатки
     ➡️ Напрямок: летить в бік центра
     ```
5. **Поиск источников**:
   - Находятся 3 наиболее релевантных сообщения из кластера.
   - Генерируются прямые ссылки на эти сообщения в Telegram.

### 3. Интеграция в `main.py`

- После того как сообщение прошло основные фильтры, вызывается `context_analyzer.analyze_context()`.
- Если контекст найден (уверенность > 50%), он добавляется в начало сообщения, отправляемого пользователю.
- К сообщению также прикрепляются ссылки на первоисточники.

**Пример итогового сообщения:**
```
**Контекст події:**
🎯 **Тип:** Шахед
📍 **Локації:** Шишковка

**Оригінальне повідомлення:**
шишковка, внимательно

**Схожі повідомлення:**
• [Джерело](https://t.me/...)
• [Джерело](https://t.me/...)
```

## Преимущества этого подхода

- **Обучение на лету**: Анализатор не требует предварительного обучения. Он использует **реальные, живые данные** из истории сообщений.
- **Кросс-канальный анализ**: Система способна связать сообщения из разных пабликов в одно событие, повышая достоверность.
- **Адаптивность**: Анализатор автоматически подстраивается под новые типы угроз и лексику, как только они появляются в пабликах.
- **Не требует отдельной обратной связи**: Качество анализа напрямую зависит от качества и полноты собранной истории.

## Как использовать

1. **Загрузить историю**: Администратор должен один раз выполнить команду `/admin_load_history`. Это может занять продолжительное время.
2. **Готово**: Система начнет автоматически анализировать контекст для всех релевантрых сообщений.

## Будущие улучшения

- **Предрасчет embeddings**: Можно добавить фоновый процесс, который будет создавать и сохранять embeddings для всех новых сообщений в `historical_messages`. Это ускорит анализ.
- **Более сложная кластеризация**: Использовать алгоритмы вроде DBSCAN для более точного выделения кластеров событий.
- **Взвешивание источников**: Добавить "рейтинг доверия" для каждого канала, чтобы более авторитетные источники имели больший вес при анализе.
