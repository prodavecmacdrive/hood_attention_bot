# Система оптимизации по районам - Вариант 1

## ✅ Реализовано:

### 1. База данных
- ✅ Добавлено поле `mode` в `user_settings` (personal/optimized)
- ✅ Таблица `district_optimized_keywords` (усредненные ключевые слова)
- ✅ Таблица `district_optimized_examples` (усредненные ML примеры)

### 2. Методы БД (database.py)
- ✅ `get_user_mode()` / `set_user_mode()` - управление режимом
- ✅ `get_optimized_keywords()` - получить оптимизированные слова района
- ✅ `get_optimized_examples()` - получить оптимизированные ML примеры
- ✅ `clear_optimized_*()` - очистка перед обновлением
- ✅ `add_optimized_*()` - добавление оптимизированных данных
- ✅ `get_district_users()` - все пользователи района
- ✅ `get_optimization_stats()` - статистика по районам

### 3. Алгоритмы оптимизации (admin_help.py)
- ✅ `optimize_keywords_for_district()` - топ-20 самых популярных слов
  - Подсчет частоты использования
  - Вычисление веса (% пользователей)
  - Сортировка по популярности
- ✅ `optimize_ml_for_district()` - кластеризация embeddings
  - K-means на всех ML примерах района
  - До 10 типичных примеров (центроиды кластеров)
  - Выбор ближайших реальных примеров к центроидам
- ✅ `optimize_all_districts()` - массовая оптимизация

### 4. Админ-команды (main.py)
- ✅ `/admin_optimize` - запуск оптимизации всех районов
  - Показывает прогресс
  - Отчет по каждому району
- ✅ `/admin_stats` - статистика по районам
  - Топ-10 активных районов
  - Общая статистика пользователей

### 5. Пользовательский интерфейс
- ✅ Кнопка "🔄 Режим" в главном меню
- ✅ Меню выбора режима со статистикой

- ✅ Callback-обработчики переключения режима
  - Проверка наличия оптимизированных данных
  - Подтверждение переключения

### 6. Логика проверки сообщений
- ✅ Обновлен `message_handler`
  - Проверяет режим каждого пользователя
  - Использует соответствующие данные (personal/optimized)
  - Логирует с указанием режима

## 📋 Инструкция по использованию:

### Для пользователей:

1. **Первичная настройка:**
   ```
   /setup → выбор каналов → выбор района → ключевые слова
   ```
   По умолчанию режим: **personal**

2. **Переключение режима:**
   - Нажать кнопку **🔄 Режим**
   - Выбрать **Персональный** или **Оптимизированный**
   - Увидеть подтверждение

3. **Персональный режим:**
   - Использует только ваши ключевые слова
   - Использует только ваши ML примеры
   - Полный контроль

4. **Оптимизированный режим:**
   - Топ-20 слов всех пользователей района
   - До 10 усредненных ML примеров
   - Автоматически улучшается с ростом пользователей

### Для администратора:

1. **Оптимизация данных:**
   ```
   /admin_optimize
   ```
   - Запускается вручную (по требованию)
   - Обрабатывает все районы с пользователями
   - Показывает детальный отчет

2. **Просмотр статистики:**
   ```
   /admin_stats
   ```
   - Топ-10 активных районов
   - Общее количество пользователей
   - Уникальные слова и примеры

3. **Когда запускать оптимизацию:**
   - После регистрации нескольких новых пользователей
   - Периодически (раз в неделю/месяц)
   - По запросу пользователей

## 🔄 Как работает оптимизация:

### Ключевые слова:
```
Пользователь 1: ["обстрел", "взрыв"]
Пользователь 2: ["обстрел", "воздушная тревога"]
Пользователь 3: ["взрыв", "ракета"]

→ Оптимизированные (топ-20):
   1. "обстрел" (вес: 0.67, используют 2 из 3)
   2. "взрыв" (вес: 0.67)
   3. "воздушная тревога" (вес: 0.33)
   4. "ракета" (вес: 0.33)
```

### ML примеры:
```
5 пользователей → 50 примеров
→ K-means кластеризация → 10 кластеров
→ Для каждого кластера выбирается центроид
→ 10 типичных примеров вместо 50
```

## 🐛 Troubleshooting:

**Проблема:** "Для вашего района еще нет оптимизированных данных"
**Решение:** Админ должен запустить `/admin_optimize`

**Проблема:** "no such column: mode"
**Решение:** Удалить `bot_config.db` и перезапустить бота

**Проблема:** Оптимизация возвращает 0 слов
**Решение:** Пользователи должны добавить ключевые слова через /setup

**Проблема:** ML примеры не оптимизируются
**Решение:** Нужно минимум 5 примеров в районе для кластеризации
